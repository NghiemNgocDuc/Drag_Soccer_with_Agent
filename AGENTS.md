# Agent Soccer — Project State

## One-line
Browser-based 2v2–11v11 3D soccer game where human/AI players take turns kicking, powered by pymunk physics. Players have 4 point-buy stats (Size/Power/Weight/Agility) that meaningfully differentiate gameplay.

## Architecture

- **Backend**: Flask (Python), pymunk physics engine, SQLite + SQLAlchemy
- **Frontend**: Three.js 3D rendering via HTML templates, shared SoundManager (`static/sound.js`)
- **AI models**: 7 agents (greedy, minimax, bayes, monte_carlo, q_learning, value_iteration, policy_iteration) — all use `simulate_kick` for lookahead evaluation
- **Auth**: Flask-Login, custom user model with registration/login
- **3D-only**: All 2D game templates deleted (`index.html`, `online.html`, `replay.html`). Route `/` redirects to `/play3d`.

## What's in place

### Core engine (`models/soccer_logic.py`)
- Per-player stats system: Size→radius, Power→kick_vel, Weight→mass, Agility→player_friction (pivot joint max_force)
- `inject_player_stats(state, team_a, team_b)` called at match start
- Stats persist through `_reset_players` and `_reset_outfield` (goal/half resets)
- Recoil formula: `recoil_vx = -cos(angle) * power * 1.2 * (power_stat/50)`
- Loft/vertical: `_loft_angle(power)` → 0 deg below power=40, (power-40)*0.5 capped at 30 deg above
- **Airborne friction fix (Path B)**: `ball_pivot.max_force` reduced to 10% (1000→100) while `ball_z > 0`, restores on touchdown. This lets lofted passes cover full field distance.
- **Formation push (Path B→C→resize)**: Team A FWD at x=605, Team B FWD at x=795 — **absolute 95px from center** (`FIELD_W/2 ∓ 95`), NOT a width ratio, so the tuned kicker-to-ball gap survives the 1400-wide field. GK/DEF/MID remain width ratios (0.062/0.162/0.281 etc.) and auto-widened with the field — the gap between lines grew (more open space) while the kicker gap stayed 95px (Power=20 floor preserved). Power=20 can still reach the ball (max travel ~95px).

### Formation system
- `_home_positions(count, side)` generates realistic soccer formations with GK, DEF, MID, FWD rows
- Supports 1–11 players, spreads outfield across y-range proportionally
- Index 0 = GK always; indices 1+ = outfield by row (defenders, then midfielders, then forwards)

- **Bounce-sound guard**: trajectory frames carry `b` as the *player-position array*; only bounce frames have `b === true` (set in `_sim`). Bounce audio must check `ptA.b === true`, or it fires on every animation frame.

### Cosmetic Referee (wandering, ball-dodging, zero physics)
- **Server motion** (`models/soccer_logic.py`): `_referee_step(ref_body, ball_body, dt)` — deterministic (no RNG, so `simulate_kick` lookahead stays reproducible): (1) ball stopped within 60px → radial dodge away at 300px/s; (2) moving ball → perpendicular sidestep away from ball's path (dead-center → deterministic side by `ry > by`); (3) else flow patrol `(sin(ry*0.02), cos(rx*0.02))` at 75px/s. Bounces off `_REF_*MIN/MAX` bounds, goal-mouth band guard pulls it out, clamp after each step. Constants: `_REF_WANDER_SPEED=75`, `_REF_DODGE_SPEED=300`, `_REF_PATH_TRIGGER=75`, `_REF_NEAR=60`, `_REF_GOAL_SAFE_X=70`, `_REF_GOAL_SAFE_PAD=12`.
- **No physics presence**: referee is a shape-less `pymunk.Body` (no Circle shape, no pivot) — the ball/players can never collide with it (previously built via `_make_player` so the ball could bounce off the invisible referee).
- **Trajectory sync**: every trajectory frame carries `"ref": {x, y}` (init frame + per-step); `_sim` steps the referee after each 3×`space.step`; state synced in `apply_kick`; sent off-field `(-100,-100)` during penalty shootouts; `game/session.py::push_snapshot` snapshots it (undo/restore).
- **Rendering**: dark slate capsule + white chest band + head + soft shadow, rendered in both `index_3d.html` and `replay_3d.html`. Live game: positioned from `/state` referee (init/reset/undo/setMode/post-move) and lerped from `ref` frames during trajectory animation. Replay: positioned from `ref` frames (init scans for the first *real* trajectory — tournament sims interleave empty placeholder moves — and autoplay now continues past empty moves, a pre-existing bug).
- **Testability hooks** (module-scope is invisible to CDP): `window.triggerAI` (also fixes the latent aivai-button bug — inline `onclick` can't see module-scope functions), `window.__refereePos()`, `window.__replayMeta()`.
- Verified headless (CDP): mesh exists + positioned == `serverToWorld(state.referee)`, wanders during AI-vs-AI and replay autoplay, hidden during penalties, zero console exceptions.

### Ball bounce feel & animation (both 3D templates, client-side only)
- **Catmull-Rom ball path**: server decimates trajectories to ~100 points (`step = len//100`, soccer_logic.py:958) — a full 500-frame flight keeps every 5th point, so linear per-segment lerp faceted the arcs. `animateTrajectory3D` now builds `THREE.CatmullRomCurve3` from the trajectory (server-space `(x, y, z)`) when `len >= 3` and samples `getPoint(progress/totalSegments)` per frame; z is clamped `>= 0` so the curve can't dip underground at bounce points (2-point paths fall back to lerp). Ball position/lights/sound flags all still derive from the same `progress` — no physics or sound-trigger changes.
- **Ball spin**: ball is a plain white sphere — spin was invisible AND absent. Added procedural canvas texture (`makeBallTexture`, 256×128: white base + dark pentagon patches + equator/meridian seams, `SRGBColorSpace`) and per-frame rotation: `rotateOnWorldAxis(cross(horizontalDir, up), dist/BALL_R)` — angle = distance/radius so roll and flight both read naturally.
- **Ground-bounce squash + dust**: `.b === true` flags **wall** bounces only (2D near-wall detect, soccer_logic.py:832-850) — ground bounces (z→0) carry no flag, so squash/dust detect the z→0 crossing client-side (`prevBz > 0.5 && bz <= 0.5`). On impact: non-uniform spring scale (`scale.y = 1−0.18·sin(π·t/9)`, x/z +0.09·…) over ~9 frames + a 10-particle dust puff (`triggerDust`/`tickDust`, lazy `THREE.Points`, time-based lifetime — frame-based lifetimes linger at low fps). Squash resets on every `animateTrajectory3D` entry; wall-bounce sound logic untouched.
- **Shadow refinement**: replaced hard-edged flat circle with a radial-gradient `CanvasTexture` blob that **fades with height** (`opacity = 0.3·clamp(1−bz/250, 0.35, 1)`) and **grows slightly** (`scale = 1+bz/350`), replacing the old size-only `max(0.2, 1−bz/200)`.
- **Testability hooks**: `window.__ballFX()` on both pages (quat/scale/shadowOpacity/shadowScale/dustActive/pos).
- Verified headless (Playwright, port 5094, seeded in-memory tournament + real `apply_kick` trajectories): 19/19 checks — lofted drive (bzMax 74-81, squash peak exactly 0.823 = designed spring, dust fires on bounces, spin > 1 rad, shadow 0.21 opacity at height vs 0.3 grounded, scale 1.21 at height), pure rolls (no flight, NO squash, dust=0, rolling spin), replay + play3d fps ~6.5 (parity with unmodified page at ~10 in this SwiftShader env — measured via git stash A/B: no regression), zero console errors / 4xx. ### Auto-Detected Match Highlights (shareable replay clips, no video)
- **Zero video**: a highlight is just a pointer — a start/end *entry index* into the match's stored `replay_data` (the interleaved move list) + label. No files, no encoding, nothing added to `models/soccer_logic.py` or live gameplay; the replay viewer's full-match behavior is unchanged (additive UI only).
- **Detection** (`db/highlights.py`): `detect_highlights(replay_data)` runs on-demand from the stored match, then cached in Redis for 24h (`highlights:{tid}:{match_id}`; share registry `highlight:{hid}` → `{tid, match_id, type, kick, start, end, label}`). Share id = `sha1(tid:match_id:type:start:end)[:12]` — deterministic, so repeated fetches return identical lists. Expires with the match replay (24h TTL).
- **Heuristics** (tunable constants, calibrated against real AI sims — measured kicks 400–1060 px/s, ~50% of AI kicks are zero-speed no-ops): **goal** = the stored `scored` flag, clip window = ±1 real move (edge-clamped, `GOAL_LEAD_MOVES`/`GOAL_TAIL_MOVES`); **near miss** = reached within `NEAR_LINE_MARGIN`=100px of the goal line AND closest approach to the mouth segment ≤ `NEAR_MOUTH_DIST`=100px AND max speed ≥ `NEAR_MIN_SPEED`=400 px/s AND attacking-direction check (mover `b` targets x=20, `a` targets x=1380); **fast play** = max speed ≥ `FAST_PLAY_MIN_SPEED`=700 px/s **absolute** (percentiles unreliable with ~50% no-op kicks) — the scoring kick is never double-listed as fast.
- **Speed derivation**: trajectories are decimated (~100 frames, `step_est = round((len−1)/100)`); `max_speed` = peak per-frame `dist * 60 / step_est`.
- **Routes** (`app.py`): `/matches/<tid>/<match_id>/highlights` (JSON API) and `/highlight/<hid>` (renders the replay viewer pre-seeked to the clip). Both match the existing replay privacy model (`@login_required` on `/replay3d/...`) — shared links are never more/less exposed than full replays.
- **Replay viewer UI** (`replay_3d.html`): Highlights section = per-kick timeline markers (`#hl-strip` cells tinted //, click to jump, `current` outline follows playback) + card list (Watch / Share — clipboard copy w/ `Copied!` feedback). `playHighlight` seeks to `h.start`, autoplays through `h.end`, then stops with a "clip finished" banner + Watch-Full-Match button. Deep links (`?highlight=<h>`) autoplay the clip on load; `window.__hlState()` test hook.
- **Tests** (`test_highlights.py`, 13): goal window + edge clamping, near-miss vs slow-roll exclusion, wrong-direction exclusion, fast-play-yet-goal exclusion, wedged/single-frame safety, cache determinism + share-id roundtrip, missing-match → None, JSON API 302/200, highlight page 302/404 flow + clip render.

### Model Leaderboard (public ranking of submitted custom AI models)
- **What it is**: cross-user ranking of user-submitted models. A model's score = **mean of its 7 per-opponent win rates** vs the built-in agents — exactly the `win_rate_a` `run_model_battle` already computes (no second scoring system). Per-opponent breakdown stored for drill-in.
- **Cost reality (measured)**: ~56 s per simulated game on this machine ⇒ a 7-opponent × 5-game benchmark ≈ **35 min**. So: no live/per-edit recompute. Submission is an **explicit owner button** ("Submit to Leaderboard"/"Re-benchmark" on each My Models card) that spawns a daemon thread (`app._run_leaderboard_bench` → `services/game_analytics.benchmark_model_vs_builtins`, pure orchestration reusing `run_model_battle`; core Arena evaluation untouched) and reports progress via Redis key `lb_bench:{model_id}` (2h cap, in-memory fallback). Frontend polls `/api/models/user/<id>/leaderboard-status` every 5 s.
- **Opt-in & privacy**: new `submitted_to_leaderboard` flag on `user_models` (separate from `is_public`); private models never appear. Public ranking rows live in a **separate `model_leaderboard` table** (migration_leaderboard.sql) so a ranked model's private `code` is never exposed via read-by-public RLS — the row holds only name/score/details/user_id + `on delete cascade` from `user_models`. RLS: anyone can select, owner manages own.
- **Backend** (`db/leaderboard.py`): `save_submission` (upsert), `remove_submission`, `get_submission`, `get_entry_detail`, `list_leaderboard(limit, offset, sort)` — sort `score` (default) or `recent` (benchmarked_at); owner join to `profiles` for username + `avatar_url` (same pattern as the player leaderboard). ### Ranked Matchmaking (human players, ELO — separate from the AI-model board)
- **What it is**: ranked 1v1 queue for registered accounts + a human ELO leaderboard (`/leaderboard/ranked`, distinct from the AI-model board). Casual `/online/create` + invite flows untouched — the rating hook only fires when `room["ranked"]` is set. Sudden-death shootout always yields a winner, so ratings are win/loss only.
- **ELO**: `E_a = 1/(1+10^((Rb−Ra)/400))`, `R' = R + K·(S−E)`; start 1200, no floor/clamp. K=40 while `games_played < 10` (placement), K=20 after. Rating deltas are `round()`ed per player (e.g. 1400 vs 1200 both provisional: winner +10/−10).
- **Placement**: rating hidden from the public leaderboard until `PLACEMENT_GAMES=10` ranked games; owner still sees rating + n/10 progress on `/profile`.
- **Queue** (Redis, in-memory fallback extends `sismember`; `sadd` returns added-count): `ranked:queue` (set), `ranked:join:{uid}` (join timestamp), `ranked:rooms` (set), `ranked:match:{uid}` (matched room id, TTL 60 s). `RANKED_QUEUE_TTL=3600`, `RANKED_MATCH_GRACE=60`.
- **Matching** (`app._try_ranked_match`): runs on every queue join **and status poll**; greedy adjacent pass over rating-sorted waiters (closest ratings first); window = wider of the two players' wait thresholds — 0–10 s ±50, 10–30 s ±150, 30–60 s ±300, 60 s+ ±600. Lower-rated player is always A (deterministic). Names come from `profiles.username` via `_profile_names`.
- **Stale reclamation** (`_reclaim_stale_ranked`): ranked room with `kick_count==0` older than the 60 s grace → both players back in the queue, room deleted.
- **Rating integrity**: ratings are written **only** from `online_move` after `apply_kick` sets `game_over` (server-authoritative; no client request can report a result). `ranked_processed` flag makes it idempotent; on storage failure `ranked_pending=True` and the next `GET /online/<room_id>/state` poll retries (`ranked_pending` retry block). Result payload (incl. `player_a/b` deltas, k, scores) stored as `room["ranked_result"]`. Guests (`guest:*`) are rejected from the queue (403); `clerk:*`/`dev:*` allowed.
- **Storage** (`db/ranked.py` + `texts/migration_ranked.sql`): `ratings` (rating/games_played/wins/losses/peak_rating), `ranked_matches` (`room_id unique` → idempotency), `rating_history` (full log for future seasons), RPC `submit_ranked_result` (single transaction, RLS: owner reads own row, leaderboard reads placed rows). `get_rating(s)`, `list_leaderboard` (placed-only, joins `profiles` for username/avatar — same pattern as `db/leaderboard.py`), `get_rating_history`, `record_result` (in-memory fallback via `_MEM`/`_MEM_MATCHES`/`_MEM_HISTORY`). **Must run `texts/migration_ranked.sql` in the Supabase SQL editor** — dev/tests use the in-memory fallback.
- **Routes** (`app.py`): `POST /ranked/join` (403 guest, 409 already in an active ranked room), `POST /ranked/cancel`, `GET /ranked/status` (idle/waiting{wait_s}/matched{room_id, my_side, opponent, opponent_rating}), `GET /api/leaderboard/ranked?limit&offset` (placed only + `placement_games`), `GET /leaderboard/ranked` (HTML page). All `@login_required`.
- **UI**: Play Ranked button + status line in the online lobby (`index_3d.html`, `RANKED` JS block: `rankedJoin`/`updateRankedStatus`/`pollRankedStatus`/`enterRankedMatch`/`rankedCancel`; 5 s status poll while waiting); delta + new rating shown in the winner banner (`RANKED.delta` captured from `ranked_result` in `pollOnline`); `/leaderboard` tab bar gained a "Ranked (ELO)" tab; `/profile` 6th stat card (ELO + placement n/10 progress + link).

### Ranked Seasons (periodic soft resets, archived leaderboards, season rewards)
- **What it is**: ranked play is organized into time-boxed seasons. Each season has its own per-player stats (`season_ratings`: start/current rating, games/wins/losses, peak). At season end the leaderboard is frozen into a JSON snapshot, rewards are granted, ratings soft-reset, and a new season starts. Everything else (matchmaking, ELO math, queue, `ratings` career rows) is untouched.
- **Timing**: `SEASON_LENGTH_DAYS=56` (8 weeks). Season 1 starts at first boot/`initialize()` (idempotent; also resumes a crashed transition tail). A `_season_watcher()` daemon thread (60 s loop) + lazy `run_transition_if_due()` on ranked/leaderboard requests runs the boundary — no cron required.
- **Soft reset**: `new = 1200 + (old − 1200) × 0.5` (`SOFT_RESET_COMPRESSION=0.5`, Python `round`) — applied only to `ratings.rating`; career `games_played`/`wins`/`losses`/`peak_rating` **never reset** (so placement + K math are permanent — once placed, always placed). Each reset writes a `rating_history` row (`match_id` null, `season_id` set).
- **Rewards** (granted once per season via `db.achievements.award` — unique `(user_id, key)` guard makes it idempotent): `sn_participant` "Season Player" (≥ `PARTICIPANT_MIN_GAMES=5` ranked games that season), `sn_top_10` "Season Top 10" (placed finish rank ≤10 → also unlocks **aurora goal effect**), `sn_champion` "Season Champion" (placed rank 1 → also unlocks **titanium ball**). Guests never awarded/reset. Toast key `season_summary` ("Season N ended — you finished #R — …") via `push_toast`.
- **Transition safety** (`db/seasons.py transition()`): (1) mark season `completed` + write `leaderboard_snapshot` FIRST; (2) grant rewards; (3) reset ratings from the frozen snapshot (not live rows — a player's final rating is exactly what the archived board shows); (4) `_create_next_season()` only if missing. Redis lock `season:lock` (300 s) prevents double-runs; re-running on an already-completed season is a safe no-op. Snapshot ordering: `rating desc, wins desc, user_id asc`; `placed` = season games ≥ `PLACEMENT_GAMES` (10).
- **Storage** (`migration_seasons.sql`, repo root): `seasons` (number unique, status active/completed, leaderboard_snapshot jsonb, RLS) + `season_ratings` (unique `(user_id, season_id)`, RLS) + `rating_history.season_id` (nullable FK). **Must run `migration_seasons.sql` in the Supabase SQL editor** — dev/tests use `_MEM_SEASONS`/`_MEM_SEASON_RATINGS` in-memory fallback.
- **Routes** (`app.py`): `GET /api/leaderboard/ranked?season=current|all|<number>` (default current; completed seasons served from the frozen snapshot; `all` = original career board; 404 unknown number) — response carries `season`/`seasons`/`viewing`; `POST /api/seasons/_transition` (**DEV_MODE only**; default job-style — no-op unless due; `?force=1` ignores the clock); `_ranked_payload` carries `season: {number, status, ends_at, ends_in_s}` on `/ranked/status`.
- **UI**: `/leaderboard/ranked` season bar (Season N tag + live countdown + select: current / archived / all; past seasons render an "archived final standings" banner); `index_3d.html` Play Ranked line shows "Season N • ends in Xd Yh"; `/profile` 7th stat card "Seasons Played" + ranked placement note now shows best season finish + "Season N is live — ratings soft-reset each season"; `customize.html` gained Titanium ball + Aurora goal effect options (gated).

### Player & Model Analytics Dashboard (public `/analytics`, small-sample-honest)
- **What it is**: a public data-science page over the game's own data answering 4 questions with defensible stats: (1) do stat builds (Size/Power/Weight/Agility) correlate with wins, controlling for skill? (2) which built-in AI agent is strongest, and is there a non-transitive rock-paper-scissors cycle? (3) do players improve, which rating brackets are hardest, and how do seasons retain players? (4) goals/match, first-goal timing, and near-miss→goal conversion. Methodology writeup: `ANALYTICS.md`.
- **Data sources (all existing, no new schema)**: `match_summaries` snapshots (lineups, winner, `ranked_result` ratings, `first_goal_kick`/`total_kicks` added by this task), `ranked_matches`/`rating_history` (per-match pre-match ratings → skill control + trajectories + brackets), `seasons.leaderboard_snapshot` (frozen boards → season pairs), `model_leaderboard.details` (custom-vs-builtins), tournament `replay_data` (ephemeral near-miss stats, 24 h TTL — stated on the page). New db read fns: `db.summaries.list_summaries`, `db.ranked.get_all_ranked_matches`/`get_all_rating_history`.
- **Stats methodology** (`services/analytics.py`, pure functions, scipy only for fisher/chi2/binomial): Wilson 95% CI (`wilson_ci`), Poisson CI for rates (`poisson_ci`), Fisher's exact when n<30 else chi-square with Yates (`proportion_test`), k×2 `group_proportion_test` (chi2 if expected cells ≥ 5 else Fisher best-vs-worst; degenerate tables → no p, honestly). Floors: 10 matches / 10 per-archetype / 8 trajectory games / 5 bracket matches / 3-kick near-miss window; every number below a floor ships with a `directional only` label.
- **Archetype bucketing**: manual & explainable — lineup signature = per-stat mean across a side's 3 players; archetype = stat with largest positive deviation ≥ 10 pts else `Balanced` (k-means rejected: unstable/opaque at realistic n). **Skill control**: the build test is re-run stratified by median pre-match rating (only when ≥ 20 rated sides) — a build effect that survives both strata is the strongest claim allowed; causal language is refused otherwise.
- **Agent matrix cost (measured ~9 min / 21 pairs × 5 games)**: never computed on a request — on-demand background thread (`POST /api/analytics/matrix/recompute`, 409 while running) + Redis cache 24 h + honest `not_computed` state; mirrors the leaderboard-bench pattern. Non-transitivity probe = strict-majority directed edges searched for 3-cycles (deduped), explicitly labeled *candidate*. Custom models judged vs the built-in-vs-builtin distribution per opponent (mean + range), not an absolute bar.
- **Caching**: `an:data` TTL 24 h, invalidated at the end of `_save_match_summary` (page is at most one match stale); warm reads ~3 ms vs ~5 s cold. Public like `/spectate`; aggregates only — no per-account lineups/trajectories.
- **Routes** (`app.py`): `GET /analytics` (public page), `GET /api/analytics` (cached payload + `cached` flag), `POST /api/analytics/matrix/recompute` (`@rate_limited`). **Bug fixed during verification**: `get_tournaments()` returns bare list rows without `matches` — the payload now resolves each via `get_tournament(t["id"])`.

### Loss Analysis ("why did my model lose this match?" — decision traces + 3D turn viewer)
- **What it is**: for a logged-in user's own uploaded models, every turn that model kicks in an arena battle / leaderboard benchmark / tournament sim is captured as a *decision trace* — the exact pre-kick physics state the model saw, its `get_ai_move` decision, the resulting trajectory, and whether it scored. A 3D viewer (`/loss-analysis` → `replay_3d.html` loss mode) replays each traced turn against the stored snapshot, tags the outcome, shows what minimax (or any built-in) would have done at the same turn, and rolls the model's turns up into loss patterns. **Physics and the AI sandbox contract are untouched.**
- **Capture boundaries (confirmed)**: traces are only written when `participant_id` / arena side starts with `user_model:` — never for guests/anon, playground, or live hvai. Retention is 30 days / ~200 recent matches per owner (pruned by `db/decision_traces.prune_expired` app-side; `unique(match_id, turn)` makes re-saves idempotent and re-orders deterministic re-runs by a fresh `created_at` stamp).

### Achievement-Gated Cosmetics (cosmetic unlocks as achievement rewards)
- **What it is**: a handful of special variant values across 6 customization categories are locked behind achievements — giving badges real stakes. Approved mapping (10 gates, 6 fields), every category keeps ≥1 always-free option and defaults are never gated:
  | Unlocks | Required achievement |
  |---|---|
  | `ball_design: gold` | `rk_first_win` (Ranked Debut) |
  | `ball_design: pixel` | `ai_first_bench` (Into the Arena) |
  | `ball_design: titanium` | `sn_champion` (Season Champion) |
  | `crowd_palette: rainbow` | `sk_big_win` (Rout) |
  | `bg_scene: cyber` | `ai_first_model` (Hello World) |
  | `grass_shade: neon` | `friend_match` (Rivals to Friends) |
  | `goal_effect: fireworks` | `tour_champion` (Champion) |
  | `goal_effect: aurora` | `sn_top_10` (Season Top 10) |
  | `floodlight_color: red` | `rk_streak_3` (On a Roll) |
  | `floodlight_color: purple` | `rk_rating_1400` (Silver Ladder) |
- **Derived availability, no new tables**: `UNLOCK_REQUIREMENTS: dict[(field, value) → achievement_key]` in `db/customization.py` + `_REWARD_LABELS` (human labels) + reverse `COSMETIC_REWARDS: {key → [labels]}`. `locked_values(user_id)` / `is_unlocked(user_id, field, value)` query `user_achievements` directly via `db.achievements.get_earned` — a single fast read, no unlock-state table that could drift.
- **Server-side enforcement** (`/customize/save`): a payload setting a gated field to a locked value → **403 + clear error naming the required achievement** (entire save rejected, nothing persisted). Non-gated values and `player_stats` pass through untouched. Grandfathering: a gated value already stored before this feature is never wiped by later unrelated saves.
- **Frontend** (`customize.html`): page route passes `lock_map` (every gate + its achievement name/description) and `locked` (`"field:value"` list for the current user). JS `applyLocks()` disables locked `<option>`s (grey + tooltip "Locked — unlock by earning X"), appends a ` …` note row under each gated select; `saveSettings()` has a client-side guard (flash error, no submit) — server remains the authority. No locked-state existed before (all plain selects) — all additive CSS/JS.
- **Toast reward mention**: `_ach_toasts()` (app.py) enriches drained badges with `unlock: ["Gold ball", …]` from `COSMETIC_REWARDS`; `static/achievements.js` renders a blue "Unlocked: …" line under the toast name (badges with no reward don't get the key).
- **Dev-mode fix (pre-existing gap)**: `db/customization.py` previously returned `ok: false` and persisted nothing without Supabase — added `_MEM` in-memory fallback to `get_customization`/`save_customization` (same pattern as ranked/leaderboard/achievements), so dev/tests genuinely persist.

## Stat→physics maps

```
Size    → radius:      12 + (stat/100)*16      → 15.2–24.8 px
Power   → kick_vel:     5 + (stat/100)*10      → 7.0–13.0 px/s/unit
Weight  → mass:         3 + (stat/100)*4        → 3.8–6.2
Agility → friction:  1000 + (stat/100)*1000    → 1200–1800
```

All linear, 1.5–1.86× range from min(20) to max(80).
